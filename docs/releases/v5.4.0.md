# AI Sales OS v5.4.0

## 客户 ID 统一客户身份

- 新增标准客户 ID 字段，并兼容 `Buyer ID`、`buyer_id`、旧平台客户 ID、买家 ID、采购商编号等常见表头。
- 客户识别统一采用“客户 ID 优先、电话号码兜底”：有客户 ID 时，导入更新、WhatsApp 绑定、Customer Brain、Lead Intelligence、Customer Success Agent、自动化和客户智能分析都使用同一客户档案；只有客户 ID 缺失时才按标准化电话号码匹配。
- 同一客户 ID 的多次导入会更新同一客户，即使姓名或电话号码发生变化也不会新建重复客户。
- 客户 ID 与电话号码分别指向不同客户、同一客户 ID 已被多个旧客户占用或人工编辑产生重复时，系统停止自动合并并要求人工核对，避免串错消息、分析和跨板块记忆。
- 升级时只增量补充字段、索引和全局身份投影；旧表中已有 Buyer ID 自定义列会回填到标准字段，不自动删除或合并历史客户。

## 分板块模型与 Token 成本控制

- 默认使用一个全域 Provider、模型和推理深度，保持旧版行为与设置兼容。
- 关闭“所有板块使用同一模型”后，可分别配置：
  - Customer Operations：客户列表、WhatsApp Inbox、邮件 Inbox、自动化群发。
  - Insights：知识库、客户智能分析。
- 每个板块覆盖项同时保存 Provider、模型和推理深度；未覆盖或无效配置安全回退到全域默认。
- 不同 Provider 的请求使用各自 Windows 凭据，不共享或暴露 API Key。

## 推理算力与思考深度

- 拉取模型时解析 API 模型目录明确返回的 reasoning / thinking 能力元数据。
- 支持展示 API 声明的 `none`、`minimal`、`low`、`medium`、`high`、`xhigh`、`ultra` 和 `max`。
- OpenAI 风格能力使用 `reasoning_effort`；声明嵌套 reasoning / thinking 协议时使用对应请求结构。
- API 未声明可调档位时只显示“自动”，不猜测、不试发收费请求，也不把未知参数发送给模型。
- 保存的档位若因模型切换或 API 能力变化而失效，请求前自动回退为模型默认。

## 实际生效范围

- 客户列表：Customer Brain 人工分析。
- WhatsApp Inbox：AI 会话助理与 Customer Success Agent。
- 自动化群发：AI 触达话术生成；普通群发与调度不耗 AI Token。
- 知识库：图片 OCR；文本入库、审批和检索不耗 AI Token。
- 客户智能分析：事实提取、商业分析、销售策略与报告生成。
- 邮件 Inbox：当前收发与同步不调用 AI，配置为后续邮件摘要/回复能力预留。

## 升级与发布边界

- 旧版 `DeepSeekModel`、Active Provider 和模型目录继续作为全域默认，不执行破坏性迁移。
- 客户 ID 数据迁移和客户身份投影均为增量写入；旧数据冲突会保留原记录并阻断自动绑定，不执行破坏性合并。
- 不覆盖 `%LOCALAPPDATA%\WAFlow\waflow.db`、客户、WhatsApp/邮件账号、消息、API 配置、自动化、报告或知识库数据。
- 仅发布 GitHub Windows 中文安装包与 Velopack 自动更新资产；不安装或重启本机正式程序。
- macOS 发布继续暂停。
